Spacing & type tokens — a proposal for the operator skills section

Measured against the live page at 1280×720. Colour, font-family, radius and shadow are the site's own :root values, copied unchanged. The only new tokens are spacing, line-height and letter-spacing. Content and colour are untouched.

0 — What the audit found

The site already has a real token layer: colour, shadow, radius, fonts, easing, --section-pad. What it has no tokens for is spacing and type rhythm — and that is exactly where the incoherence shows.

This one section currently uses nine distinct spacing values: 4.8, 5.6, 17.6, 18.7, 20.16, 22.4, 24, 35.2 and 43.2px. None of them are round, because they are all em-derived — so the same intended gap computes to a different pixel value depending on the font-size it happens to sit next to. That is the mechanism behind the wonkiness, not carelessness.

1 — Spacing: eight tokens

Fixed rem on a 4px base. Eight is the useful ceiling — enough for micro, component and section rhythm, few enough that two developers reach for the same one. --section-pad stays fluid and unchanged; section padding legitimately scales with viewport.

3 — Line-height: the finding that matters most

A line-height of 1.7 is currently inherited by every element in the section, including single-line labels. That is the root cause of the spacing looking arbitrary, and it is invisible in devtools unless you go looking for it.

Concretely: .skill-leg is 11.2px text in a 19.04px line box. That's 7.8px of leading the element carries with it — roughly 3.9px above and below the glyphs. So the 4.8px margin you wrote renders as about 8.7px of visible space. Every label on the page is silently padded by a different amount, because the phantom leading scales with each element's own font-size.

Fix the leading and your spacing tokens start meaning what they say. Four values cover the whole page:

RoleNowProposedWhy
Display heading, ≥32px1.14--lh-tight · 1.1At display size the default gap between lines is visually oversized; tightening keeps the headline reading as one object.
Long-form prose1.7--lh-prose · 1.7Unchanged. At a 672px measure this is correct and it's part of the site's voice.
Card body copy1.55--lh-normal · 1.55Unchanged — already right. Short measure, small block; 1.7 here would make each card feel disconnected.
Single-line labels & titles1.7--lh-ui · 1.25The fix. Removes the phantom leading from .eyebrow, .skill-name and .skill-leg so margins are the only thing creating space.

4 — Letter-spacing: a function of size and case

RoleNowProposedWhy
Display, ≥32px-0.012em--ls-display · -0.02emLarge type needs tightening; the gaps that read as correct at 17px read as gaps at 36px.
Body & card copy, 14–19pxnormal--ls-flat · 0Unchanged. The optical band where the face is drawn to be read.
Monospace — .skill-name+0.01em--ls-flat · 0Never track monospace positively. The even glyph advance is the point of the face; adding to it makes it look accidentally broken rather than deliberately wide.
Uppercase, ≤13px0.17 / 0.12em--ls-caps · 0.12emCaps have no ascender–descender variety to create rhythm, so small caps need positive tracking. One value, not two.

The rule behind the table, for anything not listed: tracking is inversely proportional to size — negative above 32px, zero in the 14–19px band, positive only for uppercase at 13px and below, always zero for monospace. Leading is inversely proportional to size and directly proportional to measure.

5 — Three layout findings, separate from the tokens

  • Card text is misaligned with the prose by 25px. Measured on the live page: the heading and prose start at x=96, but the first card's text starts at x=121 — the card border is aligned instead of the card copy. It's a soft misalignment you feel without being able to name. The grid is now outdented by exactly one card-padding plus the 1px border, so all three land on 96.
  • The two card rows are different heights — 282px and 236px — so the block reads as two mismatched bands rather than one module. grid-auto-rows: 1fr makes all seven equal.
  • The outdent has one precondition: the gutter must exceed it. The live gutter is a 1088px max-width with a 24px floor — 96px at 1280, 24px at 1100 — which is correct as it stands. But the outdent is 25px, so at narrow widths the cards would overhang by 1px. Either raise the floor to 32px (done here via --gutter) or drop the outdent below the 4-column breakpoint. Worth catching before it ships, because it only appears in a band of viewport widths.
  • The empty eighth slot is correct as-is. Seven items in a four-column grid will always leave one gap; centring the last row would break the left edge every other element on the page shares. Left-aligned and open is the right read — worth stating so nobody "fixes" it later.

the operator skills

devague keeps score; operators make the moves

Around the CLI sit seven operator skills — authored in the devague repo, broadcast to the AgentCulture mesh — one per leg: /scope surveys before the frame, /think walks an idea to an exported spec, /challenge pressure-tests that exported spec for blind spots before planning, /spec-to-plan walks the challenged spec to an exported plan, /assign-to-workforce fans the plan out to a parallel workforce, /deviate stops the run when execution must leave the plan, and /summarize-delivery closes the loop.

Note what devague itself never does: orchestrate. devague plan waves only describes the dependency graph — deterministic metadata, nothing more. Spawning agents, managing worktrees, gating merges: that is the operator's job. The tool that keeps score should not also play the game.

  • /scope

    idea → scope

    survey the surfaces the idea touches before framing — each finding lands on the frame citing what was actually read

  • /think

    idea → spec

    drive the frame engine — announce, capture, interrogate, park; export once the frame converges

  • /challenge

    between spec and plan

    run a risk-scaled blind-spot pass over the exported spec — findings land proposed for the human, and a clean pass records the lenses examined and the residual uncertainty, never a claim of no unknown unknowns

  • /spec-to-plan

    spec → plan

    drive the plan engine — tasks that cover every confirmed target, with acceptance criteria and honest dependencies

  • /assign-to-workforce

    plan → build

    fan the plan's waves out to parallel agents in isolated git worktrees, with TDD-gated merges — the human owns three gates: the spec, the split plan, the final PR

  • /deviate

    during the build

    stop the run the moment execution must leave the plan; the approved departure lands on the ledger before work resumes

  • /summarize-delivery

    after the build

    record planned versus actual, mid-work decisions, classified drift, and evidence-backed claims — on complete, partial, and failed runs alike
